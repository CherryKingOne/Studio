# 00 项目总览与需求范围

> 项目代号：**NovelCast**（中文名：声书工坊）
> 文档版本：v0.1（评审稿）
> 日期：2026-11-12
> 状态：**待评审，未进入开发**
> 说明：本阶段只规划后端，前端技术栈未定，不在本次范围。

## 1. 项目信息

| 项目项 | 内容 |
| --- | --- |
| 一句话定位 | 把中文小说文本批量加工成多角色有声书的本地化制作平台 |
| 项目形态 | 前后端分离；本期只实现后端 API 与 Worker |
| 项目根目录 | `/workspace` |
| 后端目录（英文） | `/workspace/backend` |
| 后端语言 | Rust（Edition 2021，stable toolchain） |
| Web 框架 | Axum + Tokio |
| 数据库 | MySQL 8.0（utf8mb4） |
| 对象存储 | RustFS（S3 兼容，Path-Style） |
| 音频处理 | FFmpeg / ffprobe（子进程调用） |
| 部署方式 | 单机 Docker Compose（mysql + rustfs + api + worker） |
| 任务队列 | MySQL 任务表（`SELECT ... FOR UPDATE SKIP LOCKED`），不引入 Redis |
| TTS 引擎 | 多引擎可插拔，MVP 先实现 Edge-TTS Provider |
| 文档目录 | `/workspace/docs` |

## 2. 背景与目标

### 2.1 背景

小说转有声书的人工流程通常包括：拆章、逐段校对、判断旁白/对白、给每个角色配音、逐段合成、拼接、响度处理、导出。人工操作时，同一本书往往需要重复处理大量文本与音频，效率低且难以复用。

### 2.2 产品目标

| 编号 | 目标 | 判定方式 |
| --- | --- | --- |
| G1 | 一条流水线完成「导入 → 切章 → 切段 → 角色识别 → 音色分配 → 批量 TTS → 拼接 → 导出」 | 一本 3 章样例书可从上传走到 ZIP 导出，无需手工改数据库 |
| G2 | 多角色配音可管理、可局部覆盖 | 旁白、角色默认音色、段落级音色三级生效；单段可重合成 |
| G3 | 生产任务可观测、可恢复、可重试 | 任务有进度、状态、错误信息；进程重启后未完成任务可继续 |
| G4 | TTS 引擎可替换 | 统一 `TtsProvider` 端口；新增引擎不改业务层 |

## 3. 目标用户与典型场景

### 3.1 目标用户（MVP）

- 个人创作者 / 小型有声书工作室。
- 单管理员账号使用，不做多租户、不做注册流程（管理员由环境变量初始化）。

### 3.2 典型场景

1. 上传一本 TXT 小说，系统自动切章、切段、识别对白与角色。
2. 在章节编辑页修正段落，给未识别的对白指定角色。
3. 给旁白和角色选择音色，试听后保存。
4. 对整章发起批量合成，实时查看进度；失败段落单独重试。
5. 合成完成后拼接为章节 MP3，检查响度与停顿。
6. 整书导出 ZIP（每章一个 MP3 + 封面 + manifest）。

## 4. 术语表

| 术语 | 含义 |
| --- | --- |
| 书籍 Book | 一部小说，聚合章节、角色、音色设置 |
| 章节 Chapter | 书籍下的一个章节，对应一个最终音频文件 |
| 段落 Segment | 合成的最小单位。旁白或一句/一段对白 |
| 旁白 Narration | 非对白文本，默认使用旁白音色 |
| 对白 Dialogue | 引号内的对话文本，绑定到具体角色 |
| 角色 Character | 书中人物，拥有名字、别名、默认音色 |
| 音色 Voice | TTS 引擎提供的发音人（如 `zh-CN-XiaoxiaoNeural`） |
| Provider | TTS 引擎适配器（edge / azure / openai / minimax） |
| 缓存键 Cache Key | 文本 + 音色 + 参数 + 引擎的 SHA-256，用于音频复用 |
| 任务 Job | 一类异步生产任务（导入解析、整章合成、拼接、导出、角色识别） |
| 母带处理 | 拼接时的响度归一（LUFS）与编码参数统一 |

## 5. MVP 功能范围

### 5.1 范围内功能（FR）

#### A. 书籍与文件

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| FR-A01 | 书籍 CRUD | 创建、查看、编辑、软删除；字段含书名、作者、简介 |
| FR-A02 | TXT 导入 | multipart 上传；≤50MB；自动识别 UTF-8 / GB18030；异步解析 |
| FR-A03 | 封面上传 | jpg/png/webp，≤5MB，存入 RustFS |
| FR-A04 | 书籍统计 | 章节数、段落数、已合成数、总时长、当前状态 |
| FR-A05 | 列表与筛选 | 分页、关键词、状态筛选 |

#### B. 文本处理

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| FR-B01 | 自动切章 | 主正则匹配「第X章/回/节/卷/篇」；无匹配时按长度兜底；首章前内容归入「前言」 |
| FR-B02 | 章节查看/编辑 | 查看标题与正文；正文可编辑（受状态保护，见 FR-B06） |
| FR-B03 | 重新切章 | 仅允许在未产生音频时执行，需 `confirm=true` |
| FR-B04 | 段落切分 | 空行优先；超长段落按句末标点切分；单段 ≤300 字（可配置） |
| FR-B05 | 段落分类 | 自动标记 `narration` / `dialogue`；混合段落按引号边界拆分 |
| FR-B06 | 重新切段 | 章节已有音频时需先失效音频；重建后旧段落软删除 |

#### C. 角色与音色

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| FR-C01 | 规则角色识别 | 从对白归属句式与别名表推断说话人，输出置信度；低置信度留待人工确认 |
| FR-C02 | 角色 CRUD | 名字、别名数组、性别、年龄段、描述、颜色标签 |
| FR-C03 | 角色音色绑定 | 每个角色一个默认音色；支持批量按性别推荐 |
| FR-C04 | 旁白音色 | 书籍级默认；章节级覆盖字段预留（MVP API 暂不开放） |
| FR-C05 | 段落级覆盖 | 音色、情绪、语速、音调、音量可单段覆盖 |
| FR-C06 | 音色目录同步 | 从 Provider 拉取音色列表并 upsert 到 `voices` |
| FR-C07 | 音色试听 | 固定 30 字样例文本，同步合成返回 MP3 |

#### D. TTS 合成

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| FR-D01 | 单段合成 | 单段落合成/重新合成，创建异步任务并返回 `job_id` |
| FR-D02 | 整章批量合成 | 三种模式：`missing`（仅未完成）、`failed`（仅失败）、`all`（全部） |
| FR-D03 | 多引擎可插拔 | `TtsProvider` trait；MVP 实现 edge，其余预留注册位 |
| FR-D04 | 合成缓存 | `sha256(provider + voice + text + 参数)` 命中即复用，不重复计费/合成 |
| FR-D05 | 失败重试 | 指数退避（2s/4s/8s），最多 3 次；超限标记 failed |
| FR-D06 | 进度推送 | SSE `/jobs/{id}/events`，推送进度、当前步骤、完成/失败摘要 |
| FR-D07 | 任务取消与重试 | 取消置 `cancel_requested`；失败任务可重新入队 |
| FR-D08 | 并发与限流 | 全局 TTS 并发数可配；Provider 级速率限制；登录接口限流 |

#### E. 音频后期与导出

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| FR-E01 | 段落音频试听/下载 | 鉴权代理下载，支持 Range（MVP 可先全量返回） |
| FR-E02 | 章节拼接 | 按顺序拼接已完成段落，可配置旁白/对白/章末停顿 |
| FR-E03 | 响度归一 | 默认 `I=-16 LUFS, TP=-1.5, LRA=11`，可配置 |
| FR-E04 | 章节元数据 | ID3：书名（album）、作者（artist）、章节名（title）、序号（track） |
| FR-E05 | 整书导出 | ZIP：`001-章节名.mp3` + `cover.jpg` + `manifest.json` |
| FR-E06 | 导出记录 | 查询导出状态、下载文件、删除导出记录 |

#### F. 任务与系统

| 编号 | 功能 | 说明 |
| --- | --- | --- |
| FR-F01 | 任务列表/详情 | 按书籍、类型、状态筛选；含进度与错误 |
| FR-F02 | 任务取消/重试 | 仅对 queued/running/failed 的合法状态生效 |
| FR-F03 | 登录鉴权 | 单管理员；Argon2id 密码；JWT Bearer，默认 24h |
| FR-F04 | 修改密码 | 需旧密码；修改后旧 Token 仍可用至过期（MVP 限制） |
| FR-F05 | 健康检查 | `/healthz`（存活）、`/readyz`（依赖可用性） |
| FR-F06 | 统一错误 | 统一错误码、消息、`request_id`；全局中间件注入请求 ID |

### 5.2 明确不做（Out of Scope）

| 不做项 | 说明 |
| --- | --- |
| 前端页面 | 前端技术栈未定，本期仅输出 API 契约 |
| 多用户/注册/权限体系 | 仅单管理员；表结构预留 `users`，不做 RBAC |
| 音色克隆 | 需要额外模型与授权，后续接入本地模型时再设计 |
| BGM / 音效 / 多轨混音 | 后续阶段 |
| EPUB / DOCX 解析 | MVP 仅 TXT |
| M4B / 分段章节合集 | MVP 仅 MP3 + ZIP |
| 云端多实例 / K8s | 单机 Compose；架构保留水平扩展空间 |
| 付费、计费、统计报表 | 不做 |
| 移动端 / 客户端 | 不做 |
| 实时录音 / 人工配音上传 | 不做 |

## 6. 非功能需求（NFR）

| 编号 | 类别 | 要求 |
| --- | --- | --- |
| NFR-01 | 性能 | 单机 4C8G 可运行；TTS 并发默认 4，可配置；FFmpeg 并发默认 2 |
| NFR-02 | 性能 | 100 万字文本导入解析按章节分批处理，内存占用与整书大小解耦 |
| NFR-03 | 可靠性 | 进程重启后，`running` 但心跳超时的任务自动回收为 `queued` |
| NFR-04 | 可靠性 | 任务与业务数据变更在明确事务边界内；音频先落对象存储再更新数据库 |
| NFR-05 | 一致性 | 段落文本/音色/参数变更必须使 `cache_key` 变化，旧章节音频标记失效 |
| NFR-06 | 安全 | Argon2id 密码；JWT ≥32 字节密钥；CORS 白名单；上传大小与类型限制 |
| NFR-07 | 安全 | FFmpeg 仅通过参数数组调用，禁止 shell 拼接；SSML 文本必须转义 |
| NFR-08 | 可观测 | 结构化日志（JSON 可选）；日志含 `request_id` / `job_id` / `book_id` |
| NFR-09 | 可扩展 | 新增 TTS 引擎只需实现 Provider 并注册，不改 Service 层 |
| NFR-10 | 兼容性 | MySQL 8.0+；FFmpeg 6.0+；RustFS S3 Path-Style |
| NFR-11 | 时间 | 数据库统一 UTC 存储；API 返回 ISO-8601 UTC 字符串 |
| NFR-12 | 字符集 | 全库 `utf8mb4`；支持中文标点、生僻字（4 字节） |

## 7. 关键约束与假设

1. **Edge-TTS 为非官方免费接口**，存在限流、协议变更、不可用风险；MVP 用它跑通链路，正式商用应切换 Azure TTS（Provider 已抽象）。
2. 仅处理**中文小说 TXT**；章节标题规则以中文「第X章」为主，允许自定义正则。
3. 单管理员、单机部署；不做水平扩展，但任务队列使用 `SKIP LOCKED`，后续可多 Worker。
4. RustFS 使用 S3 兼容协议 + Path-Style；若实际镜像端口/路径不同，只改配置，不改代码。
5. 音频统一为 MP3；段落音频来自 Provider，章节音频统一重编码。
6. 所有金额/计费相关能力不做，因此不记录 Provider 计费。

## 8. 验收总则（Definition of Done）

一个功能被视为完成，必须同时满足：

1. 代码通过 `cargo fmt --check`、`cargo clippy -- -D warnings`、`cargo test`。
2. 对应 API 在 `docs/04-api-design.md` 中有请求/响应/错误码定义，实现与文档一致。
3. 涉及的数据库变更通过 migration 落地，可重复执行（`sqlx migrate run`）。
4. 关键流程有集成测试或可复现的手工验收步骤。
5. 日志不打印密码、JWT、对象存储密钥。
6. 文档同步更新（接口、流程、状态机任一变化都必须更新文档）。
